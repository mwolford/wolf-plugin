# ADO safety rules (shared by all backlog skills)

1. Read the target work item before proposing edits. For Features/Epics read linked children; for Stories read the parent and dependencies.
2. Treat comments as input, not approved requirements, unless clearly confirmed.
3. Never update a work item until the user has reviewed the proposal and explicitly asks to apply it.
4. Show updates field-by-field (current -> proposed).
5. Never invent owners, dates, estimates, story points, dependencies or technical constraints. Ask, or label as assumption.
6. If ADO tools are unavailable, ask the user to paste the work item text.
